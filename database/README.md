# Database

Schema migrations run with **goose**. Query code is generated by **sqlc**.

## When to use what

| I want to... | Tool | Command |
|---|---|---|
| Add/alter a table or column | goose | `just migrate-create <name>` |
| Add or change a query | sqlc | edit `queries/`, then `just generate` |

---

## Schema changes (goose)

### Create a migration

```sh
just migrate-create add_pinned_messages
```

This creates a timestamped file in `database/migrations/`. Edit the `-- +goose Up` and `-- +goose Down` blocks:

```sql
-- +goose Up
ALTER TABLE messages ADD COLUMN pinned_at TIMESTAMP;

-- +goose Down
ALTER TABLE messages DROP COLUMN pinned_at;
```

Migrations run automatically on startup. You can also run them manually:

```sh
just migrate           # apply pending migrations
just migrate down      # roll back one
just migrate status    # show current state
```

---

## Query changes (sqlc)

### Write a query

Add a named query to the relevant file in `database/queries/`:

```sql
-- name: GetPinnedMessages :many
SELECT id, discord_message_id, content, pinned_at
FROM messages
WHERE pinned_at IS NOT NULL
ORDER BY pinned_at DESC;
```

### Regenerate

```sh
just generate
```

This updates the files in `database/sqlc/`. The generated code is ready to use immediately — import the `sqlcdb` package and call the function.

### Return type annotations

| Annotation | Returns |
|---|---|
| `:one` | Single row — errors if not found |
| `:many` | Slice of rows |
| `:exec` | Nothing (INSERT / UPDATE / DELETE) |
| `:execrows` | Rows affected count |

## Directory layout

```
database/
  migrations/     ← goose migration files — edit these
  queries/        ← sqlc input SQL files  — edit these
  sqlc/           ← generated Go code     — never edit by hand
  database.go     ← existing hand-written DB layer
  migrate.go      ← goose runner wired into app startup
```

> **Never edit files in `database/sqlc/` directly.** They are overwritten every time `just generate` runs.
